GitHub token

Як зробити GitHub token для адмінки ProMedia

Token потрібен для того, щоб адмінка могла зберігати зміни в GitHub-репозиторіях субдоменів. Це персональний ключ доступу, тому кожна людина має створювати власний token, а не користуватися чужим.

Важливо: GitHub покаже token лише один раз після створення. Його треба одразу скопіювати й зберегти в безпечному місці.

Рекомендований варіант

Fine-grained token

Відкрити GitHub
  1. Зайдіть у свій акаунт на github.com.
  2. Натисніть на аватарку праворуч угорі і відкрийте Settings.
  3. У лівому меню внизу відкрийте Developer settings.
  4. Відкрийте Personal access tokens.
  5. Оберіть Fine-grained tokens і натисніть Generate new token.
  6. У полі Token name напишіть ProMedia subdomains admin.
  7. У полі Resource owner оберіть акаунт або організацію, де GitHub показує потрібні репозиторії.
  8. У полі Expiration оберіть строк дії, наприклад 90 days або 1 year.
  9. У Repository access оберіть Only select repositories.
  10. Позначте потрібні репозиторії: promedia-communities, Journalism2026, promedia-jobs і за потреби promedia-subdomains-admin.
  11. У Repository permissions поставте Contents: Read and write. Поле Metadata зазвичай буде Read-only автоматично.
  12. Натисніть Generate token.
  13. Скопіюйте token і вставте його в поле GitHub token в адмінці субдоменів.
Якщо потрібних репозиторіїв не видно у списку, попросіть власника репозиторіїв додати вас як collaborator. Якщо після цього fine-grained token все одно не бачить потрібні репозиторії, використайте classic token нижче.

Запасний варіант

Classic token

Якщо GitHub не дає створити fine-grained token або потрібні репозиторії не обираються, можна використати classic token.

  1. Відкрийте Developer settings → Personal access tokens → Tokens (classic).
  2. Натисніть Generate new token (classic).
  3. Для публічних репозиторіїв достатньо поставити scope public_repo.
  4. Якщо якийсь репозиторій приватний, потрібен scope repo.
  5. Не ставте зайві права, якщо GitHub прямо не просить: delete_repo, admin:org, workflow.
  6. Натисніть Generate token, скопіюйте token і вставте його в адмінку.

Безпека

Що пам'ятати

  • Token треба берегти як пароль.
  • Не надсилайте token у відкритих чатах і не публікуйте його в документах.
  • Якщо token загубився або потрапив не тій людині, його треба видалити на GitHub і створити новий.
  • Для іншої людини краще створити окремий доступ до репозиторіїв, щоб її token можна було відкликати без зміни вашого доступу.
